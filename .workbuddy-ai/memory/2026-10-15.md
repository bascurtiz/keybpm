## Mix-it FX: SCR button → Forward Cutter (DeBaDeBa)

User asked to make the BABY scratch (SCR button on the Traktor deck FX strip in `src/components/dj/TraktorMixer.tsx`) a **cutter** instead, modeled on djay Pro's DNA pattern shown in the screenshot (`DeBaDeBa DeBaDeBa`).

`triggerBabyScratch()` in `src/lib/dj/deck-engine.ts` was rewritten to:

- Span **2 beats at current BPM** (so the effect feels tied to the track's pulse at every tempo — 70 BPM ≈ 1.7s, 180 BPM ≈ 0.67s).
- Split into **8 sixteenths** matching the `DeBaDeBa DeBaDeBa` notation.
- For each 16th: forward scratch at `+3.2x` for the first ~72%, then `setCrossfadeGain(0)` + `scratchMove(0)` for the remaining ~28% (the cut / "e" and "a" slices).
- Crossfader is reset to 1 at the top of every chop and at the end, so the user's normal xfade position is restored when the effect finishes.
- FLUX / resume logic preserved: if it was playing (or FLUX is on), it restarts after the cutter ends.

State tracking via `lastSixteenth` + `inCut` flags so each transition runs exactly once per 16th — no thrashing on RAF jitter.

Tooltip on the SCR button updated in `TraktorMixer.tsx` to "Vinyl Forward Cutter — 4 chops per beat (DeBaDeBa)".

`triggerBabyScratch` itself was NOT renamed (would be a breaking change to the engine API and other call sites would need updating). Only its behavior changed; the method name will be misleading going forward — consider renaming in a follow-up.

Key files touched:
- `src/lib/dj/deck-engine.ts` (lines 1491-1567)

## Follow-up: SCR retuned against a real reference recording

User supplied `D:\Music\keybpm-test\cutter.wav` and said the SCR effect must sound like that. Analyzed it with Python (scripts at `D:\Music\keybpm-test\analyze_cutter.py` and `detect_direction.py`).

**Measured reference (1.042 s, 44.1 kHz stereo):**
- 8 play segments, 8-9 cut segments
- play ≈ 51-62 ms (mean 56 ms), cut ≈ 58-68 ms (mean 66 ms)
- cell (play+cut) ≈ 126 ms → 8 cells ≈ 1.008 s
- 8 sixteenth-note cells = 2 beats ⇒ reference tempo ≈ 119 BPM
- **Cuts are NOT silent.** cut max_abs ≈ 0.14-0.26 vs chop peak ≈ 0.39 → the cut carries roughly 45% of the chop level. That continuous low-level reverse audio is the defining character of this cutter (buzzy, not stop-start).
- Chops alternate 51 ms / 61 ms (the D/B distinction in "DeBa"); zcr differs (8.0 vs 4.8). Too fine to reproduce reliably via RAF, so averaged into one uniform cell.

**Implementation** (`triggerBabyScratch` in `src/lib/dj/deck-engine.ts`):
- BPM-locked to **2 beats** (8 cells), so at the reference's ~119 BPM it reproduces cutter.wav almost exactly, and stays rhythmically usable at other tempos instead of drifting.
- `PLAY_FRACTION = 0.459` (56/122), `PLAY_RATE = +3.2`, `CUT_RATE = -1.6`, `CUT_GAIN = 0.45`.
- Per-cell state (`lastCell`, `inCut`) so each xfade/scratch transition fires exactly once per cell regardless of RAF jitter.
- FLUX/resume preserved; xfade restored to 1 on completion.

Note: the vinyl worklet already supports signed scratch rates (`src/lib/dj/vinyl-worklet.ts` — `scratchRate` is signed, negative = reverse), so the reverse cut is real reverse playback, not a fudge.

Button tooltip in `TraktorMixer.tsx` reads "Vinyl Forward Cutter — 4 chops per beat (DeBaDeBa)" — still accurate.

Method renamed: `triggerBabyScratch` → **`triggerCutter`** on `DeckEngine`, plus the local handler and call site in `TraktorMixer.tsx`. No other references remained. `tsc --noEmit` passes.
